# التطوير والمساهمة

## قواعد عملية قبل أي تعديل

1. افهم ترتيب الأنظمة قبل التعديل (خصوصًا التخطيط/الرندر/التفاعل).
2. لا تكسر `Reflection` للأنواع العامة بلا سبب.
3. اختبر التعديل على أمثلة فعلية وليس فقط اختبارات الوحدة.
4. عند إضافة وحدة جاهزة جديدة:
   - واجهة مكوّن واضحة
   - إضافة مستقلة
   - رسائل الأحداث إن لزم
   - مثال توضيحي
   - توثيق في ملف التعريف وهذا الكتاب

## أسلوب الكود داخل المشروع

- يعتمد على ECS أولًا.
- مكونات صغيرة وأنظمة واضحة.
- سلوك مرئي عبر `UNode/UBorder/UInteractionColors`.
- تجنب آثار جانبية غير متوقعة خارج الجدولة المقصود.

## فروع العمل المقترحة

- `feat/<name>` للميزات.
- `fix/<name>` للإصلاحات.
- `docs/<name>` للتوثيق.
